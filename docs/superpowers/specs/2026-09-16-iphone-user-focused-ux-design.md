# DropMesh iPhone：面向用户的信息与操作优化

状态：交互方向已确认；待用户审阅本设计稿后进入实现。

## 目标与边界

用户打开应用即可找到发送入口、最近收到的文件及可用设备。
默认界面回答“发什么、发给谁、是否完成、文件在哪里、接下来怎么办”。
技术详情保留，但按需查看。本轮仅修改 iPhone 展示与交互，不修改
身份、配对协议、连接判定、传输协议、存储位置或 Mac 行为。
保留照片与文件多选、显式确认发送、中英双语及无障碍支持。
不执行身份重置、不卸载应用；安装验证采用保留数据的覆盖安装。
TestFlight 上传不属于本轮自动执行步骤。

## 方案选择

采用“轻量重排＋渐进展示”。仅隐藏文字不能解决发送入口靠后、历史记录
操作冗长的问题；全面改版风险和验证范围过大，本轮不采用。

## 首页

顺序为：简短状态、发送照片／发送文件、正在传输（如有）、最近收到、设备。
现有外部分享待发送项在发送区域附近保留，必须确认后才能发送。
点发送入口即进入对应选择器，随后展示已选内容、选择目标、确认发送。
不增加自动发送，不改变本轮现有的收件设备选择能力。
正常状态使用一行可理解的描述；保持应用打开的接收限制用短提示保留。
连接异常、信任保存失败、需用户确认的安全状态必须直接显示，不能只藏在详情中。
本机服务未连接时不得把所有设备表述为确定离线。

## 设备

默认显示设备名称、设备类型图标和可操作的连接状态。
设备 ID 及诊断状态放入设备详情。名称未知显示“未命名设备”，不以 ID 作名称。
移除操作移入详情，保持现有二次确认和保存失败保护。
详情入口至少 44pt 可点击区域，VoiceOver 名称包含对应设备名。

## 传输与历史

活动传输显示名称或项目数、对方名称、进度、当前阶段及适用的取消操作。
已有可靠大小数据以 MB/GB 等可读单位显示；不编造速度或剩余时间。
字节已传完但接收方未确认时显示“正在确认接收”，不得提前标记完成。
已完成条目紧凑显示文件名／批量项目摘要、对方名称和时间；接收条目可点击预览。
可用的图片提供缩略图；不支持或不可用时显示文件类型图标，不能阻塞列表。
共享操作仍可找到；最近收到无需先进入完整历史。明确显示接收文件位置及现有访问方式。
技术详情含设备 ID、路由、精确字节统计和完整时间。
对方名称复用现有名称解析逻辑；无法解析时显示“未知设备”。
预览不可用、文件已移动、历史读取失败须直接提示并给出可行操作。
失败信息先解释用户可以做什么，原始诊断放详情；不得无条件提供实际无法工作的重试按钮。

## 实现约束

复用 MobileAppModel、MobileSendModel、MobileHistoryModel 的状态与命令。
视图只调整展示顺序、详情呈现和入口，不引入第二套状态机。
历史条目及设备详情以稳定 ID 标识；异步缩略图不在主线程读取大文件，
仅处理应用已有权限的本地内容，取消或条目变化后不串图。
重要状态同时用文字／图标表达，不只依赖颜色。大字体下自动纵向排布。

## 验收

1. 首页首屏可找到两种发送入口，分别直接打开对应选择器。
2. 默认设备与历史列表不展示 UUID、原始字节计数或路由；详情可查看。
3. 接收文件从首页一步进入预览；文件位置可见，缺失文件不假装可打开。
4. 发送仍需确认；多选、取消、后台中断、离线阻止发送保持现有安全语义。
5. 连接异常、保存失败、确认接收阶段不会被简化成错误的成功状态。
6. 中英文、长文件名、空列表、失败状态及辅助大字体无截断主要操作。
7. 回归单元测试、模拟器交互与截图对照通过；再构建并覆盖安装到已连接手机。
8. 分开报告代码验证、已安装、真实跨设备传输、TestFlight 发布状态。

## 自检

范围为 iPhone 渐进展示与短路径；没有新增后台能力、自动发送或多接收方协议改动。
诊断可折叠但用户必须处理的异常不可隐藏。安装不等同于真实传输验收。
