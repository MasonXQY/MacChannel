# DropMesh 新收文件快捷入口与剪贴板发送设计

日期：2026-09-03  
状态：接收快捷入口已实现并通过自动化验收；剪贴板发送待实施
目标平台：macOS 14 或更高版本；数据模型与命名不阻塞未来 Windows 客户端

## 1. 背景与目标

当前收到文件后的菜单栏绿色提示点只负责提示。用户要经过“菜单栏图标 → 传输与历史 → 历史 → 在 Finder 中显示”才能找到文件，操作路径过长。与此同时，用户有时需要发送剪贴板中的文字、图片或已复制文件，目前必须先手工创建或另存文件。

本次改动建立一套菜单栏第一层的快速收发流程：

1. 新收到的文件直接出现在 DropMesh 主菜单顶部，点击文件名即可在 Finder 中定位。
2. 主菜单提供“发送剪贴板…”入口，把受支持的剪贴板内容转换为普通传输项目。
3. 接收端始终把剪贴板内容保存为文件，不覆盖接收端剪贴板，也不自动打开内容。
4. DropMesh 只在用户主动发送时读取一次剪贴板，不进行后台监听、索引或历史采集。

## 2. 选定方案

采用“主菜单动态快捷区”方案，而不是点击绿点后直接打开 Finder，也不新增独立收件箱窗口。

直接打开 Finder 虽然点击次数最少，但当连续收到多个批次时无法明确决定应该展示哪个目标，也会让同一个菜单栏图标在有无绿点时产生完全不同的点击行为。独立收件箱能承载更多信息，但会重新引入额外界面层级。

动态快捷区保持菜单栏图标行为一致，又把常见路径缩短为“点击菜单栏图标 → 点击新文件”两步，并能正确处理多个未读批次。

## 3. 新收文件快捷区

### 3.1 展示位置与结构

存在尚未处理的新接收批次时，DropMesh 主菜单在运行状态下方、发送操作上方显示“刚刚收到”区域。该区域只在有未读接收时出现，不长期占用菜单空间。

区域内容：

- 最多展示最近 5 个新接收批次，按接收完成时间倒序排列。
- 单文件批次显示文件名；多文件批次显示“已收到 N 个文件”。
- 每项显示来源设备名称；无法解析名称时显示“其他设备”，不显示内部设备 ID。
- 每项使用接收完成图标，并具备明确的 VoiceOver 标签，例如“来自 Mason 的 report.pdf，在 Finder 中显示”。
- 超过 5 个批次时，在列表末尾显示“另有 N 个新接收项目…”。
- 区域末尾提供“查看全部历史…”，打开“传输与历史”并直接选中“历史”。

NSMenu 不适合承载复杂卡片，因此首版使用原生菜单项和简短标题，不引入悬浮卡片、缩略图或横向按钮。

### 3.2 点击行为

点击单文件项目时，在 Finder 中选择该文件。点击多文件项目时，打开这些文件的共同父目录；若文件不再存在，则退回打开当前配置的接收目录。

系统通知的点击行为与快捷区保持一致。Finder 定位失败不改变传输成功状态，也不删除历史记录。

### 3.3 未读规则

绿色提示点代表“还有用户未处理的新接收批次”，而不是“用户曾打开过菜单”。规则如下：

1. 成功接收并保存一个非空批次后，将该批次加入未读队列并显示绿点。
2. 仅打开菜单不会清空绿点。
3. 点击某个快捷项目后，只将该批次标为已处理。
4. 点击“查看全部历史…”后，将当前所有未读批次标为已处理。
5. 当未读队列为空时绿点消失；新接收会再次点亮。
6. 若用户通过系统通知点击并成功触发 Finder 定位，对应批次也标为已处理。

未读队列只保存本次应用运行期间的轻量摘要，不新增用户文件内容数据库。应用重启后不恢复绿点，但完整传输历史仍保留。

### 3.4 文件变化与设备变化

- 文件被移动或删除：快捷项仍可点击，并退回打开接收目录。
- 来源设备被移除或重命名：已生成的未读摘要保留接收时的展示名称，不因设备目录变化而消失。
- 连续收到相同文件名：每个接收批次使用其实际落盘 URL，遵循现有重名处理规则。
- 接收失败、取消、空结果或历史恢复：不得生成快捷项或绿点。

## 4. 剪贴板发送

### 4.1 用户入口

主菜单的发送区依次显示：

1. “发送文件…”
2. “发送剪贴板…”

用户点击“发送剪贴板…”后，DropMesh 才读取当前系统剪贴板并生成待发送项目，然后复用现有设备选择界面。只有一个在线设备时仍显示明确的目标选择，避免在多 Mac 环境中把敏感内容误发到错误设备；后续可另行设计“默认设备”能力。

拖放菜单栏图标的行为不变。剪贴板发送与文件发送共享现有端到端加密、局域网直连、加密中继、进度、取消和失败提示能力。

### 4.2 支持类型与优先级

一次操作只选择一种最具体的剪贴板表达，优先级如下：

1. **已复制文件或文件夹**：发送原始文件系统项目，不创建副本。
2. **图片**：优先读取可无损转换的图像数据，生成 PNG 文件。
3. **文字**：读取纯文本并以 UTF-8 生成 TXT 文件。

若同一剪贴板项目同时带有文本和图片表示，按以上顺序只发送一次，避免重复内容。首版不支持自动下载网页、转换富文本、发送 HTML、联系人、密码管理器私有类型或任意应用自定义剪贴板类型。

### 4.3 临时文件与命名

文字和图片在发送端应用缓存目录中创建受控临时文件：

- 文字：`剪贴板文字 YYYY-MM-DD HH.mm.ss.txt`
- 图片：`剪贴板图片 YYYY-MM-DD HH.mm.ss.png`

文件名使用本地时间，冲突时追加递增序号。发送端临时文件只保留到传输进入最终状态；成功、失败或取消后均尽快删除。应用异常退出留下的临时文件在下一次启动时按年龄清理。临时文件不得进入用户传输历史的“源文件定位”能力。

接收端把它们视为普通文件，自动保存到用户配置的接收目录，并沿用现有重名避让规则。接收端看到的文件名与发送端生成的名称一致；不覆盖接收端剪贴板，不自动打开 Finder 或文件内容。

### 4.4 隐私与安全边界

- 不监听剪贴板变化，不在菜单中展示剪贴板预览，不预先读取以判断菜单是否可用。
- 仅在用户点击“发送剪贴板…”后读取一次当前内容。
- 读取后仍需用户明确选择目标设备，未选择或取消时不发送。
- 日志、通知、诊断和错误信息不得记录剪贴板文字、图片数据、完整文件路径或内容摘要。
- 空剪贴板或不支持的类型显示“剪贴板中没有可发送的内容”，不创建空文件、不进入设备选择。
- 剪贴板转换失败显示本机错误，不产生传输记录。

## 5. 数据与组件边界

新增一个应用级“最近接收摘要”状态源，接收成功事件是唯一写入入口。每条摘要至少包含：稳定批次 ID、完成时间、接收时的来源设备显示名、实际落盘 URL 列表和已处理状态。

菜单栏控制器只负责渲染摘要和转发用户动作；Finder 定位继续复用现有接收目标定位能力。传输历史仍是完整、持久的事实来源，但主菜单不得通过反复扫描历史来推断未读，避免应用启动时把旧文件重新标为新文件。

剪贴板读取与格式转换由独立适配器负责，生产环境封装 `NSPasteboard`，测试使用内存实现。适配器输出普通 URL 列表，之后完全复用现有发送协调器。菜单栏控制器不直接编码 PNG、不写入文本文件，也不拥有临时文件生命周期。

数据流如下：

1. 用户点击“发送剪贴板…”。
2. 剪贴板适配器读取一次内容，按优先级生成普通发送 URL。
3. 用户选择一个在线设备。
4. 现有发送协调器完成加密传输并报告最终状态。
5. 接收端按普通文件落盘、写入历史、发出系统通知并加入未读摘要。
6. 接收端用户从主菜单快捷项或系统通知在 Finder 中定位文件。

## 6. 错误与降级

- 未连接安全服务：两个发送入口遵循同一禁用或错误提示规则。
- 没有在线设备：剪贴板内容不得丢失或被清除，提示当前没有可接收设备。
- 目标设备在选择后离线：进入现有发送失败流程并清理生成的临时文件。
- PNG 编码或临时目录写入失败：在选择设备前结束，不制造失败传输记录。
- 菜单中未读文件已经不存在：打开当前接收目录；目录也不可用时给出简短本机提示。
- 快捷菜单刷新期间有新接收：下一次菜单打开时显示；不得修改一个已由 AppKit 展示中的菜单结构而导致崩溃。

## 7. 无障碍与原生行为

- 所有新菜单项支持键盘导航，并使用原生 `NSMenuItem` 的选中和高亮状态。
- “发送剪贴板…”提供键盘快捷键，但不得与系统粘贴 `Command-V` 冲突。
- 绿色点之外，菜单栏按钮的辅助功能值继续表达“有新接收文件”。
- 快捷项的可访问名称同时说明来源、内容和动作，不能只用颜色或图标表达未读。
- 菜单点击外部区域自动关闭的现有行为保持不变。

## 8. 测试与验收

### 8.1 自动化测试

按测试驱动方式先建立失败用例，再实现：

1. 成功、失败、取消、空结果和历史恢复对未读摘要的影响正确。
2. 多次接收按时间倒序展示，主菜单最多 5 项并正确显示溢出数量。
3. 打开菜单不清除绿点；点击单项只确认对应批次；查看全部确认当前所有批次。
4. 单文件、多文件、文件丢失和接收目录缺失时的 Finder 行为正确。
5. 来源设备被移除或重命名后，未读项继续使用接收时的安全展示名。
6. 剪贴板文件、图片、文字的优先级、命名、转换和空内容提示正确。
7. 剪贴板内容仅在显式点击后读取，取消目标选择不会发送。
8. 临时文件在成功、失败、取消和应用重启清理场景下均不会泄漏。
9. 剪贴板发送复用现有在线设备校验、传输进度和错误状态。
10. 新菜单项的标题、顺序、快捷键和 VoiceOver 描述正确。

### 8.2 真实双机验收

发布前在两台安装同一候选版本的真实 Mac 上完成：

1. 分别通过局域网直连和加密中继接收单文件、多文件批次。
2. 接收后确认绿点出现，点开菜单即可看到文件，点击后 Finder 正确定位。
3. 连续接收超过 5 个批次，检查排序、溢出提示、逐项确认和查看全部行为。
4. 发送纯文字、截图图片、Finder 中复制的文件和文件夹，接收端均自动保存到指定目录。
5. 校验接收文字为 UTF-8、图片为有效 PNG、文件与文件夹内容哈希一致。
6. 在目标离线、选择后掉线、发送取消和空剪贴板场景验证错误提示与临时文件清理。
7. 检查接收端剪贴板未被覆盖，发送端剪贴板内容未被清空。
8. 通过签名、公证、装订票据的 DMG 覆盖升级，并回归配对、拖放发送、系统通知、更新检查和菜单外点击自动关闭。

只有自动化套件、正式构建检查和真实双机收发全部通过后，才能发布包含该功能的版本。

## 9. 本次范围外

- 自动跨设备同步剪贴板。
- 后台监听、剪贴板历史或内容预览。
- 接收端自动复制、自动打开或执行收到的内容。
- 网页 URL 抓取、富文本保真或应用私有剪贴板类型转换。
- 默认目标设备、广播到所有设备或无需确认的快捷发送。
- 持久化或跨设备同步未读状态。
